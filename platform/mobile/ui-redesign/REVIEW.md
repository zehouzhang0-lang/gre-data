# 当前实现与优先验证项

目前有用户对卡顿、动效和激励感的主观反馈。这里记录从代码确认的现状和可复测的假设，实际耗时等同一环境采样后再填。

## 单词墙

**搜索路径值得先量。** [WordWall.jsx](../src/components/WordWall.jsx)已把筛选结果、当前 28 张卡片和分组展示拆开缓存，普通翻页和翻面复用筛选结果。每次查询变化仍会通过 [filterEntries](../src/model.mjs)扫描词库，将词形、释义、笔记拼接并转为小写，再按当前模式排序。随机排序在比较时计算散列。先测搜索输入、筛选计算和 React 提交分别花了多久。若这些开销占主要部分，优先试复用标准化文本和排序依据。词义或笔记编辑、词库变动、筛选切换应配套验证缓存行为。结果保持同样的数量、顺序与关系组。

**每次翻页有统一的入场反馈。** [wordwall-redesign.css](../src/wordwall-redesign.css)使用 100ms 位移和淡入，并对减弱动态效果做了分支。[WordWall.jsx](../src/components/WordWall.jsx)以页码和搜索词标识页面，搜索输入也可能重建卡片页、重复入场。建议将搜索、左右翻页、fresh 三种反馈对照：搜索时光标和列表框架稳定，翻页表达方向，fresh 表达当前页的词已后移。动效与提交同步，连续操作可立即响应。

**高密度可以保留。** [design-tokens.css](../src/design-tokens.css)已有白底、青绿、三档记忆色和字体变量。四列让用户扫读快。先在窄屏检视长词断行、中文卡面、筛选计数和分页的视觉优先级，再决定调哪些间距。颜色沿用现有含义，配短标签或辅助技术可读提示。可在工具栏保留同一个 fresh 按钮作为手势的替代入口。

## 复习与刷题

**优先展示可继续的一步。** [Review.jsx](../src/components/Review.jsx)轮次卡片已有完成状态、词数、进度和继续入口。[WordSession.jsx](../src/components/WordSession.jsx)已有正确与重练反馈，并提供本轮完成词和已保存作答数。可将「继续上次步骤」「完成 X/Y 词」「下一轮复练」排成主次明确的视图。完成效果和完成词数取自已保存的轮次状态，浏览卡片数仍只表达浏览。

**区分切题中的计算与读盘。** [App.jsx](../src/App.jsx)对刷题页做了延迟加载，[Practice.jsx](../src/components/Practice.jsx)按当前题定位取详情，题目目录在交互中也会重新派生列表。[loader.mjs](../src/practice/loader.mjs)读取本地资源、验证哈希和题目定位。分别测首次打开刷题、连续切题、返回已看题和打开目录。如果详情读取成了瓶颈，可验证带题库版本的短期缓存或相邻题预取。先取得可测信号，再决定保留几题以及何时释放资源。数学图和阅读原文要覆盖加载、回退、缩放或恢复滚动位置。

**等待和失败已有状态入口。** [useRepository.js](../src/useRepository.js)的启动观察器会继续等待原初始化操作，超过 15 秒给出提示。[App.jsx](../src/App.jsx)区分写入失败与已保存但刷新失败。[Primitives.jsx](../src/components/Primitives.jsx)处理底部面板焦点。可以将这些状态的视觉规则统一后供各页复用，保留异常时可以执行的操作与可靠焦点。

## 最少测量路径

| 动作 | 记录什么 |
| --- | --- |
| 冷打开到首屏、再次打开刷题 | 本地数据读取和解析、组件启动及首屏出现的时间，冷暖分别记录。 |
| 单词墙搜索、清空、翻页、fresh | 输入或手势到新内容绘制，结果和页码正确，中文输入法组合输入，连续操作中有无丢帧或误触。 |
| 复习续接、SE/TC/RC 连切、Quant 图像 | 下一步实际内容出现时间，任务断点、草稿状态、原文滚动位置及图像占位是否稳定。 |

用同一份脱敏样例、相同设备和构建配置先后跑基线和改版。每个高频动作可先采样 20 次，记录样本数、中位数、P95 和代表性轨迹。基线和改版的运行条件分别列明。桌面 DevTools 用来定位，Android WebView 用来验收绘制与触控。
