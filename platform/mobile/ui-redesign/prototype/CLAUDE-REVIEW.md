## 二、为什么 A、B 看起来有 AI 感

这一节是判断。我对照的是 Anthropic 官方 `frontend-design` skill 里列出的默认样式清单。

- **A 是同款卡片套件。** 28 个 12px 圆角的粉彩卡，一个青绿主色，一个带图标的整宽按钮，每页一句口号。

我自己的第一稿是米白底、细线分格、衬线、朱红点缀，同样被这份清单否掉了：细线报纸版式和暖底配赭红都在上面。C 是推倒后重做的。

## 三、候选 C（第二轮）

一句话：首页只有词墙。白底，一种墨色，一种词块灰，轻触把词块翻成黑面。屏幕上唯一的彩色是三档记忆状态，默认只以一个小圆点出现，也可以切回原版的整块填色。标记、多选、分组、Fresh 都有手势，不用先进多选。

出发点是这个产品自己的样子：词墙是一块棋盘，「翻面」就是翻一枚棋子，白面英文、黑面中文；记忆状态是贴在词卡角上的一个圆点。

| 你说的 | 现在的做法 |
| --- | --- |
| 首页只留词墙，Fresh 按钮不要放在词墙下面 | 首页没有 Fresh 按钮。它在「多选 → ⋯」里，手势是双指上滑 |
| 多选、分类、标红黄绿、Fresh 都要有快捷手势 | 按住一个词，上方弹出标记条，滑到圆点上松手就标好了，不进多选。完整手势见下表 |

| 所有主动触发的积极动作都要响亮且各不相同 | 每个往前走的动作有自己的声音，响度按手机扬声器模型校准到彼此相差 2 dB 以内 |

### 标记

- 标记先写后显。写入失败时词块不变，状态位显示「没有保存，标记没有改变」。
- 标完的词如果是翻开的，会自己翻回正面。翻开、判断、标记、合上，是一个完整的小回合。
- 圆点落下时有一次小的回弹，状态行里对应的数字跳一下。
- 一页 28 个词都标过了，会多响一声，状态位显示「这一页都标过了」。
- 和正式 App 一样，标记之后词留在原位，不会因为不再符合筛选而当场消失；换筛选或搜索时才重排。

### 词墙的运动

- 词墙是一长条页面。当前页的前后两页就在视野外紧挨着，间隙与词块之间相同，所以拖动时看不出「页」的边界。
- 静止时视野只到词墙边缘，不露出相邻页的边角；一动起来视野放宽到屏幕边缘，相邻页从屏幕边上进来。
- 翻页是先换页、再滑到位：状态立刻更新，眼睛看到的位置接着走完。滑到一半再拖或再点，从当前位置接着走，不会跳。
- 到头时词墙会有阻力，松手弹回，响一声「到头」。
- 上下方向是同一套逻辑转九十度。

### 字体与字号

| 角色 | 字体 | 字号 |
| --- | --- | --- |
| 英文词、页码、计数 | Source Serif 4（已打包进原型） | 词 15 / 14 / 13 / 12，复习大词 44 |
| 中文界面 | 系统黑体 | 12–16 |
| 少数大标题 | 宋体 | 26 |

- 一个词取它能在词块内单行放下的最大一档。390 宽下每页 28 词里有 26–28 个是 15px。
- 四档都放不下的词分两行，在靠近中间的音节处断开并加连字符：两个辅音之间优先（irrecon-cilable、pusil-lanimous、quintes-sential），否则在元音之后（incontro-vertible）。这是经验规则，不是词典断词。
- 释义一个义项一行。一行放不下的义项按等长拆行，不会剩一个字单独成行。超出词块的部分用省略号截断，和正式 App 一样需要「详情」兜底。
- 用 28 个长词和长释义压测过（评审面板的演示状态里可切），没有溢出。
- 这款字体有光学尺寸，小字比大字宽，所以词宽是按实际字号逐档量的。
- 中文层级靠字号和灰度，不靠字重。很多安卓机型只带一个中文字重。

### 动效

内容先提交，动效只作用在已经上屏的内容上，新动作会打断旧动效。

| 动作 | 表现 | 时长 |
| --- | --- | --- |
| 翻面 | 词块绕纵轴翻过去 | 280ms |
| 按下 | 词块缩到 0.96 | 100ms |
| 翻页 | 跟手；松手后从当前位置滑到位 | 220–420ms，随剩余距离 |
| Fresh | 逐行升起 14px，从上到下每行晚 20ms | 每行 240ms |
| 撤销 Fresh | 反向落回 | 同上 |
| 标记条 | 从按住的词上方弹出 | 160ms |

### 音效

全部用 Web Audio 合成，没有音频文件，代码在 `src/c/sound.mjs`。

怎么做得不像电子音：

- **音符是一根马林巴音条。** 泛音取 1 : 3.99 : 10.65，这是真实音条的调音，数值来自开源的 STK ModalBar 模型。每个泛音各自指数衰减，高的比低的消失得快得多。
- **起音是软槌。** 几毫秒的渐入加一声低沉的接触声，不是一个咔哒。
- **轻敲是一小块木头。** 泛音 1 : 2.777 : 7.378，百分之几秒就没了。
- **翻页是一件乐器的一个音。** 整个音出自一个声源，不是几层叠起来的。「纸声加一下轻敲」你听出来是两段拼的，拨弦你不喜欢也嫌低，都已换掉。现在有五种候选，都是敲击音条或簧片的建模，音区都比拨弦高：卡林巴、马林巴、颤音琴、钟琴、音乐盒。五种都保留，在设置页「翻页音色」里选（评审面板的试听区也有同一个选项），Fresh 和撤销用的是同一件乐器。每种音色的音量在选中时自动校准到与其他动作等响。要加新音色，在 `src/c/sound.mjs` 的 `PAGE_TONES` 里加一项（名称、音区、余音长短、起音软硬、各泛音的比例和强弱），它会自动出现在两处选项里并自动校准音量。
- **每一页有自己的音。** 往后翻一级一级升高，往回翻降回来，和复习的音阶同样永远不会到顶。
- **有一点房间。** 四分之一秒的极短混响，声音不再是贴在耳朵上的。
- **每一下都不完全一样。** 音高有几音分、响度有百分之几的随机差别。
- **3 kHz 以上的能量占比**：除刷题那一声外都在 15% 以下。

音阶为什么不会到顶：每个音是同一个音名在几个八度里同时响，响度按一条固定的钟形曲线分配（Shepard 音）。音名一级一级往上，最高的那个八度渐渐退出，最低的渐渐进来，听起来一直在升，却永远不会变尖，也不会重复同一级。「再想想」会把它归零。

| 声音 | 何时 | 是什么 | 手机扬声器模型下的响度 |
| --- | --- | --- | ---: |
| 翻面 / 翻回 | 轻触词块 | 一声木头轻敲，翻回的低一些 | −16.2 / −14.6 dB |
| 选中 / 取消 | 多选 | 两下轻敲，上行 / 下行 | −15.2 / −14.8 |
| 词墙下一页 / 上一页 | 翻页 | 所选乐器上这一页自己的音 | −16.2 / −16.2，各级等响 |
| Fresh | 换一页 | 同一件乐器上五个音快速上行 | −16.2 |
| 撤销 | 撤销标记或 Fresh | 同一件乐器上四个音下行 | −16.2 |
| 按住 | 标记条弹出 | 两下低的轻敲 | −14.9 |
| 标记 完全忘记 / 有一点印象 / 记得很清楚 | 标记一个或多个词 | 一根、两根、三根音条上行，和环、半、满对应 | −14.9 / −15.1 / −15.0 |
| 本页标完 | 一页 28 词都标过 | 三个音加一个和声 | −15.0 |
| 复习 已保存 | 点「记得」且写入成功 | 永远上行的音阶里的下一个音 | −15.1，连续 12 级完全等响 |
| 一轮完成 | 最后一词保存成功 | 三个音上行，落在一个和弦上 | −12.9 |
| 刷题 下一题 / 上一题 | 切题 | 短、硬、快的一声「唰」 | −22.3 / −22.1 |
| 滑过选项 | 手指经过标记条上的选项 | 很轻的一下 | −21.1 |
| 再想想 / 到头 / 没保存 | 不是往前走的动作 | 更轻，音高往下 | −21.0 / −19.8 / −19.0 |

- 往前走的动作彼此相差不超过 1.9 dB；「不是这边」的那组低 3 到 6 dB。
- 所有声音峰值不超过 −4 dBFS，没有削波。
- 刷题那一声按能量算比别的低 7 dB 左右，因为它是一段窄带噪声；它的峰值与其他声音相同。它是照你喜欢的那一版原样保留的，只把整体音量提了上来。听起来偏轻或偏响告诉我。
- **这些是量出来的数，没有人听过。** 响度模型只是两个高通加一个中频提升，不是任何一台手机的实测。好不好听、像不像原生，只能由你的耳朵判断。评审面板左下有「试听全部声音」，可以逐个点，也可以切到「模拟手机扬声器」听。
- 如果合成的质感还是不够自然，下一步是换成真实乐器的录音。CC0 的 VCSL 库（<https://github.com/sgossner/VCSL>）里有真实录制的马林巴 30 个音、卡林巴 27 个音、民谣竖琴 58 个音、音乐会竖琴 45 个音，每个 WAV 约 0.9–1.4 MB。取 6 到 8 个音、裁短后放进原型就够用，下载量约 6–10 MB。我没有下载，等你同意。

触感：原型里用 `navigator.vibrate` 占位，默认关闭。它是单次马达脉冲，在很多手机上发麻。Android 官方的触感原则是宁可没有也不要发麻的振动，生产版应通过原生插件使用系统的清晰触感。

### 为容易分心的人做的几件事

你说自己容易注意力不集中。这几件事是照着这一点做的，没有连续打卡，没有彩带。

1. **屏幕上只有一件事。** 首页只有词，其余的要用的时候才出现。
2. **每个主动的动作都有回应，而且立刻。** 一声、一下动、一个数字的变化，三样同时到。
3. **一个小回合就是一次完成。** 翻开、判断、按住标记、词块合上。不用进入任何模式。
4. **一页是一个可以完成的单位。** 标完一页有单独的一声，然后双指上滑换下一页。
5. **连续答对听得出来。** 音阶一级一级往上，不占屏幕，断了才归零。
6. **今天有终点。** 复习页的标题是「今天还有 2 轮」，做完变成「今天的复习做完了」，主按钮退成描边，导航上的红点消失。
7. **做错了没有代价。** 标记和 Fresh 都能撤销，双指下滑就是撤销。
8. **主操作永远在同一个位置。** 复习的「继续」、会话里的「记得」、多选时的三个标记按钮，都在屏幕底部拇指位。
9. **进度不骗人。** 没保存就不前进，所以前进的每一格都可信。

### 深色

同一套规则反过来：深色词块，翻面是亮面。在设置页和评审面板里可切换。

## 四、检索性能

单独放在 [../search/README.md](../search/README.md)。要点：

- 正式的检索函数本身不慢，1 万词的合成词库上每次按键约 4 ms。
- 慢在界面层：每按一个键整页 28 个词块被拆掉重建，而且卡在按键事件里。
- 候选改动后，每次按键的阻塞从约 10–15 ms 降到 0.5 ms，连打五个键的总阻塞从 44–71 ms 降到约 3 ms，函数本身快 4.6–6.8 倍。结果与原版逐项相同（约 2,400 组随机筛选的等价测试通过）。
- 这些是桌面加开发模式的数字，只能看两版之间的比例。
- **正式代码没有改。** 改动是 `search/fast-filter.mjs` 和一个 4 处的补丁，已通过 `git apply --check`。

回退：恢复旧令牌和旧组件即可，不涉及数据库和学习记录。
