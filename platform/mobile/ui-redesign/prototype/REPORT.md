# 首阶段 UI 原型评审与验证

2026-11-22，候选方案，**20 项通过 / 0 项失败，隔离构建通过**。推荐 A「清爽白底」进入用户体验评审；B「纸感阅读」保留作同内容对照。尚未替换正式 App，未改真实学习记录，未提交或推送本轮候选文件。

## 最优先的三个问题

1. **操作后找不回位置。** 优先保留页码、同一批词、排序和筛选，而不只做漂亮转场。原型覆盖第 3 页 Fresh 后搜索、搜索中改变条件、清空及搜索中重载后的恢复。
2. **不同动作的反馈相似。** 搜索不启动整页动画；前后页分别左右入场；Fresh 自下向上换入，用持续可撤销反馈说明已后移。新内容立即提交，不等动画结束。这样用户能分清“查到了什么”“到了哪里”“刚把什么挪后了”。
3. **进度与下一步不突出。** 复习卡片以名称为主，已到期/今日/继续等文字补足颜色，数量与细进度条为次，右侧给继续入口。浏览和 Fresh 不增加进度。原型的数量是演示数据；正式版本必须由保存成功的真实轮次投影驱动。

第 1 项是本原型已验证的行为；第 2/3 项是设计选择。生产查询是否慢在字符串标准化、排序、React 提交还是 WebView 绘制，仍需同机基线测量，不能据本原型宣布修复。

## 两个方向与动作对照

| 项目 | A 清爽白底 | B 纸感阅读 | 共同行为 |
| --- | --- | --- | --- |
| 阅读 | 纯白底，深青字，无衬线英文；更接近现状 | 暖纸色，森林绿，衬线英文；阅读气氛更明显 | 同样168词、相同状态、4列7行；切主题不重置任何位置 |
| 搜索 | 白色输入面，青绿焦点 | 浅纸色输入面，森林绿焦点 | 行内检索，无弹窗；直接替换结果，保持焦点；清空回到搜索前条件 |
| 翻页 | 150ms，±18px淡入 | 同 A | 内容先更新；首尾禁用，连续动作中断旧动画 |
| Fresh | 180ms，自下12px入场；青绿主按钮 | 同动效，森林绿按钮 | 按钮/双指上滑；整批最多后移3页；同页展示后续词；可撤销 |
| 复习 | 轮次名、时间标签、已练数、细进度条 | 同结构，纸色画布与柔和层级 | 颜色不单独承载含义；继续从已保存位置开始 |
| 减少动效 | 关闭位移与过渡 | 同 A | 仍立即更新内容并提供文字反馈 |

Fresh 的作用域是「筛选+排序+搜索词」。搜索内 Fresh 不改变主墙顺序；清空恢复搜索前筛选、排序及原批次。原型还缓存每个搜索范围的浏览位置，正式主线目前在查询变化时重置结果页；这是候选交互的差异，不应在移植样式时悄悄改动生产规则。

## 实际检查

一轮18项检查，加2项搜索条件恢复定向检查，共20项通过。包括首屏28/168与4×7、搜索返回同IDs、筛选/排序保留、Fresh整批后移/不重不漏/撤销、尾页禁用、点击翻面、鼠标与CDP长按、CDP单指左右滑、CDP双指上滑只触发一次且无误翻面/多选、减少动效、复习7→8后切走/重载续接、练习草稿恢复、360/390无横溢及两主题截图。最初的favicon404已修正，最后定向检查无资源/console错误。

构建：Vite 7.3.6，2.44s；输出JS 255.76kB（gzip82.37kB）、CSS17.04kB（gzip4.38kB）。这是独立原型产物，**不是正式APK体积变化**。

复测：从仓库根目录运行 `node platform/mobile/ui-redesign/prototype/qa.mjs`。已启动4188服务时可运行；`--search-origin`仅补验搜索条件恢复，不重复采样。QA脚本只操作新的浏览器上下文，`QA.json`保留原始结果和样本。切换到共享目录后，Node依赖向上解析到现有安装。

## 性能记录与解释

Windows，Node24.14.0，Chrome158.0.8127.36，Vite开发模式，DPR1，外层1440×1050、手机画布390×844，无CPU限速，168合成词，暖态。两主题按相同动作各采样20次，共240个样本。原始记录在 `QA.json`。采样在搜索条件边界修复之前完成，修复后只补功能验证，不重复整轮性能采样。

下列为事件处理开始至**双requestAnimationFrame的上屏代理时间**，单位ms，格式「中位数 / P95」。它不等于物理屏幕呈现时间，也不包括用户手指滑动到识别之前的耗时。

| 动作 | A | B |
| --- | ---: | ---: |
| 搜索 | 12.00 / 13.40 | 12.30 / 14.20 |
| 清空 | 13.20 / 17.40 | 12.45 / 18.10 |
| 下一页 | 11.25 / 14.00 | 11.15 / 13.10 |
| 上一页 | 11.95 / 16.70 | 11.35 / 17.70 |

原型主路径没有人为加载等待。两套视觉在本样本下接近；不能据这些差异说某主题更快。这里**没有正式App旧版可比基线，没有真机trace，没有冷启动统计**。因此不报告加速百分比，不保证手机端达到上述时间。

正式阶段以相同脱敏规模（接近实际词量）、同一手机、相同构建方式测旧版与改版：输入到结果、组件提交、绘制分开记录。检索候选改进是建立可失效的标准化搜索文本与排序键；词义/笔记/词库修改必须更新索引，且逐项比对结果顺序与数量。先验证瓶颈再接入，不能把原型的168词成绩替代完整数据库成绩。

## 如何沿用到另外三个模块

| 模块 | 沿用规则 | 首次实测 |
| --- | --- | --- |
| 复习 | 轮次名优先，每页最多4轮，状态文字+语义色；保存后推进；继续按钮固定语义；失败不假装完成 | 认义/补全/默写真实断点，切后台重开，写入失败，完成/未完成归类；改名/取消/删除保持原数据契约 |
| 刷题 | 相邻题方向动效与词墙一致；题号、来源、草稿状态稳定；读取中有固定尺寸占位 | SE/TC/RC前后切与已做题；Quant禁横滑；阅读上下独立滚动；选词不误选答案；冷读/缓存读分别测 |
| 设置 | 同按钮/表单/焦点/错误与保存反馈；按用户任务分组 | 导出成功，导入取消，返回键，键盘遮挡；账号登录必须另做真实授权闭环 |

这里只演示单阶段认义和原创例句草稿。任务创建、编辑、删除、日程、真实GRE解析、登录都未由本原型替代。完成态中的既有演示卡仅作视觉样本；完整记录分页和所有任务操作需在正式Review组件验收。
