# 交互验收与跨模块规则

这份报告只评审合成数据原型。依据是共享目录的 README、REVIEW 和 CLAUDE-PROMPT；没有运行测试、读取真实词库或采集真机性能。下文的验收条件是待验证目标，不是通过结论。

优先解决三个问题：连续操作要保留上下文；不同手势只能产生一个明确动作；进度反馈只能来自保存成功的学习状态。建议第一阶段采用白底青绿方案，先改善层级、方向反馈和恢复路径；阅读与进度更突出的方案作为同数据对照。这个推荐基于现有视觉连续性，尚无用户比较试验。

## 首阶段最容易遗漏的状态

| 路径 | 应看到的结果 | 容易遗漏的边界 |
| --- | --- | --- |
| 第 3 页 → 行内搜索 → 清空 | 回到搜索前的第 3 页、筛选、排序和 Fresh 后的浏览顺序；输入始终在原搜索框内 | 不能只恢复页码而丢失本页词条；中文组合输入中不要抢焦点、移动光标或反复启动整页动画 |
| 连续下一页、上一页 | 内容与页码立即对应，动效仅说明方向；后一动作可中断前一动效 | 不等待动画结束才更新；边界不能首尾环绕；空结果不能出现 1/0 页 |
| Fresh 本页 | 保持当前页位置，看后续的新内容；原本这一页作为同一批往后移最多 3 页 | 不新增学习事件、不改记忆颜色；重复 Fresh 的顺序须确定；仅剩本页时禁用并解释，没有内容可替换 |
| Fresh 接近尾页 | 只后移实际存在的后续页；不重复、不漏词 | 尾页不足 28 词时，要固定批次语义并记录预期词 ID，不能因重新切片导致本页熟词又混回来 |
| Fresh → 撤销 | 恢复动作前的顺序、页码和卡片批次 | 撤销范围要明确为最近一次 Fresh；切换筛选或数据集后，不把旧快照套到新结果上 |
| 搜索中 Fresh | 必须有明确规则，不能悄悄重排全库 | 原型可采用搜索期间禁用 Fresh，清空后使用；如果要支持，须维护独立搜索结果顺序，返回主墙不受影响。最终以主线已实现规则为准，并在界面和报告说明差异 |
| 换筛选、排序、页面尺寸 | 结果数量、页码上限、当前内容保持一致 | Fresh 顺序属于哪个浏览范围必须显式定义；两套主题切换只能换视觉，不得重置浏览位置或数据 |
| 翻面、长词和长释义 | 两面不遮住其他词；完整内容可访问 | 不用裁剪隐藏唯一释义；390px 和 360px 均保持四列，系统大字号允许纵向滚动，不压缩触控目标 |
| 演示轮次继续 | 名称、完成状态、当前阶段、继续位置彼此一致 | 未完成与完成不只靠颜色；「已保存」必须由保存结果驱动。原型外壳标明演示数据，产品内不混入工程术语 |
| 少动效、键盘和辅助技术 | 状态更新仍清晰，焦点不丢失 | 少动效保留直接切换和状态提示；输入框有标签；页码/Fresh/保存结果使用克制的 live region，不朗读整墙 |

Fresh 的尾页批次、搜索作用域和撤销失效条件须在原型中用一套明确规则贯穿，不能同时展示互相矛盾的行为。此报告未读取主线最新 Fresh 实现，以上是设计边界，不是修改主线逻辑的指令。

## 手势互斥规则

优先级按当前上下文判定：输入与文本选择 → 已打开的面板 → 双指 Fresh → 单指横滑 → 纵向滚动 → 点按。长按只有在移动未越过阈值时成立。

| 输入 | 可以产生的动作 | 不应连带产生的动作 |
| --- | --- | --- |
| 单指轻触卡片 | 翻面；多选模式下改为选中 | 翻页、Fresh、两次 click |
| 长按后松手 | 进入多选并选中目标 | 同时翻面；把之后一次轻触当成第二次长按 |
| 单指横滑 | 上一页或下一页 | 纵滚时误翻页；松手触发底下卡片点击 |
| 单指纵滑 | 原生纵向滚动 | Fresh、页面跳动、多选 |
| 两指同向上滑 | 一次 Fresh | 第二指落下时沿用第一指长按计时；两指各触发一次 Fresh；松手触发卡片点击 |
| 双指缩放、反向移动或第三指加入 | 取消 Fresh 候选；交给允许的原生行为 | 将一次捏合识别成 Fresh |
| 系统取消、触点离开、页面切换 | 清除手势候选和按压反馈 | 下次触摸继承上次状态 |

阈值需要真机微调，不能把桌面合成触控的通过当成大拇指操作已通过。仅在已确认双指动作时阻止默认滚动；不要全局禁用触摸滚动。Fresh 始终保留可触达的按钮，TalkBack 使用按钮完成同一操作。

## 视觉和动效如何沿用

| 模块 | 信息与反馈 | 动效规则 | 实测动作 |
| --- | --- | --- | --- |
| 单词墙 | 工具栏稳定；颜色表达原有自评，选择态用描边/标记；页码次于内容；Fresh 后出现简短反馈与撤销 | 搜索不整页飞入；前后页有相反方向；Fresh 可用短向上位移说明后移。数据同步更新，动效可中断 | 搜索/清空、连续翻页、末页 Fresh、撤销、双指与点按互斥 |
| 复习 | 卡片首要是任务名称，每页最多 4 轮；完成与未完成分开；继续入口标出真实断点和已保存数量 | 进度仅在保存成功后前进；完成反馈短且不阻挡下一动作；紧急状态同时有文字 | 中断后继续、改名、取消、置顶、删除、写入失败后恢复；紧急色与真实到期规则核对 |
| 刷题 | 题号/来源位置稳定；草稿和已提交状态明确；长按选词不改变选项 | SE/TC/RC 方向与单词墙一致；Quant 保留按钮；资源未就绪显示稳定占位，保留草稿 | 已做题相邻前后切、阅读上下分区各自纵滚、选词、Quant 图、冷打开与返回已看题 |
| 设置 | 按任务组织；导出、导入、账号连接各自有明确状态；失败提示包含下一步 | 使用一致的焦点、面板进出、按钮按压和保存反馈；登录等待不能无限静默 | 导出结果、导入取消、错误恢复、返回键、键盘遮挡；登录需真实授权闭环另验 |

三档记忆颜色的含义贯穿两套主题。复习紧急颜色表达时间压力，必须配「待复习/已到期」等文字，不能暗示记忆能力。复习目标的修改、任务取消和删除沿用现有数据契约；视觉原型不能自行宣布真实记录已删除或已同步。

## 一轮必要的对照测量

先固定浏览器版本、机器、窗口 390×844、设备像素比、合成数据版本及条数、是否开启 CPU 限速、运行方式和少动效开关。再补一遍 360px 宽度的布局检查。两套主题使用相同顺序、相同搜索词、同一初始状态；交替测试 A/B，减少缓存顺序偏差。界面主题比较与生产性能优化分开报告。

1. 冷打开记录一次资源与首屏轨迹；暖状态用于高频动作。冷暖数字不要混算。
2. 用固定脚本各采样 20 次：输入到有结果、清空恢复、下一页、上一页、Fresh、撤销。输入计时从实际 input 事件开始，手势计时从动作被识别时开始；另外记录手势完成前的识别时长。动作间等页面进入稳定状态，不用人为等待模拟优化。
3. 分开记录计算/DOM 提交与上屏近似时间。双 requestAnimationFrame 只作为上屏代理，不能声称是精确屏幕呈现时间。保留一条代表性 Performance trace，用于解释长任务或掉帧。
4. 每项报告样本数、中位数、P95（排序后 nearest-rank，第 19/20 个样本）、正确结果校验以及最长样本原因。数据规模与生产不同则不算生产性能提升；没有可比旧版基线就不报告加速百分比。
5. 同一轮功能检查核对顺序不重不漏、搜索返回、短尾页、Fresh 撤销、少动效、键盘可达性和页面无横向溢出。只在发现失败或新增改动时追加针对性复测。

真实 Android 验收仍待完成：WebView 版本和实际刷新率、系统字号、TalkBack、输入法组合输入、键盘安全区、单手与双指手势、系统返回/暂停恢复、真实数据量下的读盘和绘制。桌面原型只能证明本原型在所记环境下的行为，不证明手机 App 已更快或登录已修复。

## 交付边界

首阶段只交付隔离原型和说明，不接入真实数据库、不改学习事件、不导入备份、不提交或推送仓库。公开或提供给 Claude 的材料只能包含合成样例、提示词及脱敏说明。需要移入共享目录时由主线在同步完成后选择成果；此文件本身没有触发同步。
