## A. 键盘弹出时单词墙不动

**原因。** Capacitor 的 `SystemBars` 在键盘弹出时给 WebView 的父视图加底部 padding，WebView 变矮，`.app-shell { height: 100dvh }` 跟着变矮，7 行 `1fr` 的卡片被压扁。同时注入的 `--safe-area-inset-bottom` 变成 0，底栏高度也会变。所以只固定高度还不够，安全区也要固定。

**做法。** 只对词墙搜索框生效：

1. 搜索框加 `data-keyboard="overlay"`。`focusin` 落在它上面时，在键盘弹出之前同步冻结：把 `.app-shell` 的高度写成当前像素值，把当前的 `--safe-top`、`--safe-bottom` 计算值内联写到 `.app-shell` 上。
2. 键盘直接盖住下方卡片、页码和底栏，它们都不上移。`html`、`body` 不能被滚动（冻结后内容比视口高）。
3. 失焦后继续冻结，直到视口高度恢复，或 500 ms 超时，再解除。这样收键盘时也不闪。
4. 宽度变化（转屏、分屏）时立即解除并重新量。焦点直接跳到别的输入框时立即解除。
5. 其他输入框（默写、分组名、设置、弹层）保持现在的行为。不要改 `windowSoftInputMode`，那会影响所有页面。
6. 空结果内容靠上排，键盘弹出时按钮要看得见。
7. 按键盘的「搜索」键时收起键盘。

顺手修同一张截图里的两处：

- 搜索框聚焦时出现框中框：去掉 input 自己的 outline，改成外层 `.wall-inline-search:focus-within` 的一圈边。
- `disquisition` 被断成 `disquisitio / n`：`fitWord` 用 canvas 量的宽度比实际渲染窄，CSS 又把它断开了。原因还没确认，可能是系统字体缩放，也可能是 Source Serif 的光学尺寸。先复现，再改用与卡片同样式的隐藏 DOM 节点测量（仍走缓存）。任何情况下不能出现单字母孤行。

验收：弹出和收起键盘的全过程中，第一张卡和最后一张卡的 `getBoundingClientRect()` 逐帧不变；结果为 0、1、6、28 词各测一次。默写页的主按钮仍在键盘上方。

## B. 把搜索的词加入词库

**先判断，再显示按钮。** 用 `shared/capture-word.mjs` 的 `capturedWord()` 规范化查询，然后查整个词库，不是查筛选结果。用户截图里「未标记」筛选开着，词可能在库里、只是被筛掉。

| 情况 | 显示 |
| --- | --- |
| 不是合法英文词或短语 | 只有「清除筛选」，没有生效筛选时不显示 |
| 词库里已有，只是被筛掉 | 主按钮「查看 xxx」，打开词详情；下方「清除筛选」 |
| 词库里没有 | 主按钮「加入词库」；下方「清除筛选」（只在有筛选时） |

- 空结果标题改成「词库里没有 xxx」；词被筛掉时写「xxx 被筛选隐藏了」。删掉「减少筛选条件，或导入你的词库」。
- 「清除筛选」只清筛选，保留查询词。现在会连查询一起清掉。
- 有近似结果但没有完全相同的词时（例如搜 `art`，只有 `artful`），用户按「搜索」键或输入框失焦后，在原来「多选」的位置显示文字按钮「加入」。打字过程中不显示，免得一直闪。

**设置。** 「设置 → 数据与备份」加一行「搜索加词：直接加入 / 先填释义」，默认「直接加入」。存进现有的 `gre-wall-appearance:v1`（字段 `addMode: 'direct' | 'meaning'`，经 `normalizeWallAppearance`），不写进学习数据。

**直接加入（默认）。** 点一下就完成，不弹窗。

- 写 `vocab_capture`，`payload = { word, source: { type: 'search' }, context: '' }`。不能用空释义的 `vocab_upsert`：它会把词标成「用户编辑」，`catalog-update.mjs` 的 `edited` 会从此跳过这个词，以后的词库更新补不进释义。
- 随后调用现有的 `repo.requestCuration([word])`，让它进「待整理」，下次词库更新可以自动补释义。这一步失败不影响已加入的词，只提示。
- 加入后卡片背面是「待补释义」，在「待补释义」范围里能找到；没有释义仍不能标记和进背词轮，这是现有规则，不变。
- 提示条：「已加入 xxx」，带「补释义」（打开详情编辑）和「撤销」（写现有的 `vocab_delete`）两个按钮。

**先填释义。** Sheet 标题就是这个词，一个自动聚焦的「中文释义」输入框（必填），一个主按钮「加入」，键盘回车等于「加入」。走 `repo.saveEvent('vocab_upsert', { word, meaning, pos: '', note: '' })`。

**两种方式共同的规则。**

- 保存前在队列里再查一次，已存在就不写，只打开详情。
- 曾被删除的同名词：按钮写「恢复 xxx」。直接方式下 `vocab_capture` 会恢复它并保留旧释义；填写方式预填旧释义。
- 成功后播放新音效 `wordAdded`，筛选清到只剩查询，新卡片出现并轻弹一次（240 ms，尊重减少动态效果）。失败时保留已输入的内容，原地显示错误并播放 `error`。

## C. 响应速度

### 目标

端到端 10 ms 在手机上做不到：触摸采样、屏幕刷新（每帧 8 到 17 ms）和音频输出缓冲都在应用之外。我们能管的是应用自己的那一段：

| 指标 | 目标 |
| --- | --- |
| 手势被识别 → 发出声音指令 | p95 ≤ 10 ms |
| 手势被识别 → 界面提交 DOM 变化 | p95 ≤ 10 ms（长列表刷新除外） |
| 手指按下 → 卡片按压反馈 | 下一帧 |
| 手指按下 → 长按条出现 | 约 180 ms（原 400 ms） |

长按必须留一段时间来区分轻点和滑动，不可能是 10 ms，所以靠“按下当帧就有反馈”让它感觉快。

### 已确认的原因和改法

1. **长按等 400 ms**（`WallTrack.jsx:6`），之后还有 160 ms 从透明淡入。
   - `HOLD_MS` 改 180。计时到点时，若手指已移动超过 6 px，就不触发长按，交给滑动判断。
   - 触摸开始当帧直接给卡片设 `data-pressed`（不经过 React），按下没有过渡，松开才有。不要依赖 `:active`。
   - 长按条首帧就完全不透明，只保留 100 ms 以内的位移。
   - 按住不到 260 ms、没移动就松手，按轻点处理：关掉长按条，翻面。
   - `Review.jsx:32` 的 480 ms 改 260。
2. **标记、撤销、建组的声音和画面等保存完才出现**（`WordWall.jsx:296-330`）。链路是：复制整份数据 → 序列化两次 → 写 SQLite → 重新投影全部事件 → 重渲染 → 才 `play`。
   - 改为乐观更新：识别当下立刻播放声音、触感，用覆盖层改卡片状态和计数，翻回正面；让浏览器先画一帧，再调用 `repo.rate()`。
   - 标记不再走 `mutate` 的 `guard` 和 `busy`。现在保存期间全部卡片禁用，第二次标记会被直接丢掉并播放 `error`。连续标记要全部排队，一次都不能丢；每次仍是独立事件，撤销仍逐次进行。
   - 刷新合并：一串标记结束后只刷新一次，用 `startTransition`。
   - 失败时撤掉该次覆盖层，播放 `error`，提示「没有保存」，已成功的不受影响。
   - 还有未完成的标记时，「撤销」要排在它们后面，不能只看旧的 `state.undoId`。翻阅记录的 `flush` 要等未完成的标记写完。
   - 「请先补齐释义」的检查保持同步、在最前面。
3. **每次翻面，最多 84 张卡全部重渲染**：`flip` 依赖 `flipped`，`select` 依赖 `selected`，`busy` 又传给每张卡。用 ref 或函数式更新让回调稳定，`busy` 不再传给卡片。验收：翻一张只渲染一张，长按只渲染这一张和长按条。
4. **切题声音等 `loadQuestion` 完成**（`Practice.jsx:134-139`）：改为手势确认时立刻播放。
5. **背词作答声音等保存**（`WordSession.jsx`）：判定在本地同步完成，所以对错的声音和反馈立刻出现。保存失败时回到现有的失败重试流程，并撤掉这次反馈。`complete` 仍等整轮真的保存完。
6. 按钮统一加 `touch-action: manipulation`；手势区维持原样。

### 测量

- 加 `performance.mark`，只在开发模式开。用合成数据（3000 词、5000 条事件）在 4 倍 CPU 降速下，报告改前改后的 p50 和 p95：翻面、长按出条、标记、连续标记 10 次、切题。
- 单次保存占用主线程超过 50 ms 时，只报告数字和耗时分布，不要改 repository 内部，由 Claude 决定下一步。

测试至少覆盖：连续标记 10 次不丢；中间一次失败只回退那一次；标记未落盘时撤销；翻阅 flush 与标记交错；重复点击不产生重复事件。

## D. 低延迟音频引擎

**现状。** 现在用 WebView 的 Web Audio 实时合成，一次翻页最多建二十多个振荡器，并额外加了 5 ms 延后。Android WebView 的输出缓冲通常不小，具体多少要在真机上看。

1. 把 `sound.mjs` 的配方离线渲染成 48 kHz 单声道 16 位 WAV，音色、音量和间隔不变（含五种翻页音色 × 五个音级、连对音阶五个音级）。开头的静音要裁掉。写成可重复运行的脚本，产物放 Android 资源。
2. 写原生插件 `LowLatencySound`，用 `SoundPool`（`USAGE_GAME`、`CONTENT_TYPE_SONIFICATION`、`FLAG_LOW_LATENCY`），启动时预加载，`play(id, rate, volume)` 不等返回。播放速率随机 ±0.2%，保留“每次略有不同”。静音立即停掉正在响的声音。多段和延后的音（例如 `pageDone`）渲染成一段或在原生侧排程。不可申请音频焦点，不能打断用户正在听的音乐。
3. `sound.mjs` 对外接口不变。Android 默认走原生；加载失败或不在 Android 时用 Web Audio。Web 路径也改成播放预渲染的 `AudioBuffer`，去掉 5 ms 延后，并指定 `latencyHint: 'interactive'`；回到前台时恢复 AudioContext。
4. 「设置 → 帮助」加一行「音效引擎：低延迟 / 网页」，供用户对比。旁边「复制诊断」只含引擎、采样率、`baseLatency`、`outputLatency` 和各声音加载状态。

交付时把“测到的数字”和“没人听过、没上真机”分开写。

## E. 刷题页音效

风格：短、硬、快、干（走 `dry`，不进房间混响），和切题的“唰”一家；响度与现有主动动作相差不超过 1.5 dB。已有动作的音色不变。

## F. 长按拖动框选，取代右上角「多选」

### 手势

1. 长按一张卡，弹出现有的长按条（标记 / 分组 / 详情），和现在一样。
2. 手指仍在“菜单区”内（起点卡片、长按条、两者之间的空隙，外扩 12 px）时：现有行为，松手执行所指的动作，没指到就关闭。
3. 手指离开菜单区：长按条立即消失，进入框选，这一次手势内不再返回菜单。向上穿过长按条继续走，也算离开。
4. 框选矩形：一角是起点卡片上最初的按压点，对角是手指当前位置，每帧更新。与矩形相交的卡片（重叠至少 6 px）被选中；手指往回缩，离开矩形的卡片立即取消。起点卡始终选中。
5. 松手：
   - 选中 2 个及以上：进入多选状态，保留选择。
   - 又缩回到只剩起点卡：取消，什么都不选，当作反悔。
6. 多选状态中：轻点增减单张；再次长按并拖动，从未选的卡开始是追加一个矩形，从已选的卡开始是移除一个矩形。多选状态不再弹长按条，一进入长按就直接框选。
7. 第二根手指落下、系统取消、切后台、返回键：取消本次框选，恢复到手势开始前的选择。
8. 只框当前页，不跨页、不自动翻页。框选期间禁止翻页、滚动和 Fresh 手势。横、竖两种翻页方向都要支持。

### 画面和声音

- 矩形：1.5 px 墨色边线、约 8% 填充、8 px 圆角，没有动画延迟。命中的卡片当帧出现选中边和 ✓。
- 移动过程中只改 DOM 属性和一个覆盖层，不触发 React 渲染；卡片位置在框选开始时量一次。松手才提交一次 state。
- 顶部原地显示「已选 N」。
- 声音看矩形的最短边，单位是卡片数：最短边 = min(选中的行数, 选中的列数)，由起点卡和矩形覆盖到的最远行、列算出。最短边每增加 1，播放一次 `marqueeGrow`；每次完全相同，不升调、不变响，也不做随机音高变化。一步跨多级时只响一次。缩小时不响。触感与声音同步。
- 例：1×1 → 1×4 一直不响；拉到 2×4 响一次，3×4 再响一次。
- 边界防抖：同一条边在 6 px 内来回抖动不重复触发；真正缩回再拉大，可以再响。
- `marqueeGrow` 用现有 `select` 同一材质的单记短敲，响度与其他主动动作一致。
- 松手进入多选时播放 `select`。

### 多选状态的界面

- 顶部：取消 · 已选 N 词 · 全选本页 · ⋯（不变）。
- 底部页码栏换成操作条，在拇指区，每项不小于 48 px：忘 / 模糊 / 记得（三个状态图标）、分组、背。点状态标记立即生效并退出多选；所选词里有缺释义的，三个状态置灰，点按提示「N 个词缺释义」。
- 翻页方向、卡片大小和位置在进出多选时都不能变。

### 入口

- 删掉右上角「多选」按钮。搜索框占满这段位置；B 的「加入」只在需要时出现。
- 「⋯」菜单里保留一项「多选」，给读屏和不方便拖动时用。
- 按词组排列的视图（grouped）目前没有长按条，本批不加框选，用「⋯ → 多选」。
