## 平台机制

以本次 source_commit 的代码为准：

1. `platform/server/store.mjs:16`、`platform/web/src/api.js:17`：身份键是 `[material, unit, question]`，不是内容指纹。
2. `platform/server/question-bank.mjs:192`：只按 key 去重；不同套题位置的同题全部保留。
3. `platform/server/index.mjs:89–95`：题库合并、已做判断和推荐均按 key，因此做过一份不会阻止另一编号被作为新题推荐。
4. `platform/server/question-bank.mjs:223–231`：逐页读取并完整覆写缓存，不是多次追加。本轮未调用会重建缓存的接口。

其他可能出现已见题的导航行为，也已确认，但没有证据表明它们是上述 16 次异编号重复的主因：

- `Practice.jsx:76`：恢复 localStorage 中停留题优先于后端推荐，可能恢复已做题。
- `Practice.jsx:157`：“下一题”按题库顺序移动，不跳过已做题。
- `QuestionNavigator.jsx:22` 与 `index.mjs:95`：单元或题型全做完时回退首题。
- 前端只认平台 attempts，后端完成集合还包含旧 Markdown 记录，可能造成旧训练完成状态显示不一致。
- 普通定时状态刷新不会单独重置当前题；复习模式的间隔重做属于另一条明确流程。
