# Android 手机接管与训练提示词

核查日期：2026-10-06（UTC+8）。适用仓库：`zehouzhang0-lang/gre-data`，同步目标分支 `main`。

状态：已检查仓库代码和官方说明，尚未在用户的 Android 手机上安装或验收。以下是可复制的提示词，不代表手机已经获得权限或已经运行服务。

## 使用路线

手机 ChatGPT 负责读取资料、指导操作与讲解；Termux 在手机上运行 Git、Node 和学习平台；手机 Chrome 打开 `http://127.0.0.1:4173/`。只要服务确实运行在同一部手机，该地址才指向手机上的平台。电脑、云端容器各自的 localhost 都不是手机 localhost。

项目访问和手机运行需要分别接通：

- 如果手机 ChatGPT 当前提供 GitHub 应用或仓库工具，先通过其实际提供的授权流程连接本仓库，再让它读取文件验证权限。工具可能只读，不能把读权限当成提交权限。
- 如果账户提供 Codex 移动端远程连接，可以配对已有电脑来读取和维护电脑上的项目。官方说明要求相应账户权限、应用版本、配对及在线电脑，功能可能分批开放；这条路线的命令仍在电脑执行，不会把平台运行到手机。[OpenAI 远程连接说明](https://learn.chatgpt.com/docs/remote-connections)、[工作树与手机的执行位置](https://learn.chatgpt.com/docs/environments/git-worktrees)。
- 手机本地部署用 Termux。先尝试原生 Termux；如果实际报原生依赖兼容错误，再评估 PRoot Linux。PRoot-Distro 官方支持在 Android 上运行 Linux 用户空间。[Termux 安装来源](https://github.com/termux/termux-app#installation)、[PRoot-Distro](https://github.com/termux/proot-distro)。
- 普通对话没有手机终端工具时，由你把命令复制到 Termux 执行，再返回非敏感输出。提示词本身不会给 ChatGPT 增加 Termux 控制能力。

依次使用提示词 1、2；安装完成后每天使用 3，结束使用 4；遇到问题使用 5。手机浏览器保存的正式作答先进入手机仓库，Git push 后其他设备才能 pull；未保存的浏览器草稿不会同步。

```text

https://github.com/zehouzhang0-lang/gre-data
同步目标为 main。请先读取本仓库 platform/mobile-prompts-20261006.md。

首先核实你本次对话实际拥有的能力，分别说明：
1. 能否读取这个仓库，能否写入，以及当前读取的分支/提交。
2. 能否执行终端命令；如果能，命令运行在我的手机、远程电脑还是云端。
3. 能否操作我的手机浏览器，还是只能给我链接和步骤。
每项给出实际工具结果或明确写“尚未验证”。不要把工具提供的 Linux 终端自动认作我的 Android 手机。

有权限时实际读取 AGENTS.md、profile.md、scores.md、SCHEMA.md、
platform/README.md、.agents/skills/gre-platform/SKILL.md，按任务读取最近记录。
报告文件中的实际考期、时间预算、模型设置，并注明读取分支/提交或来源。
没有仓库连接时，指导我使用当前客户端确实存在的授权入口；如果没有入口，
明确说明，并列出我需要提供的最小文件。不要要求我把密码、令牌或登录文件发进聊天。

我的目标是：平台在手机本机运行，Chrome 访问 http://127.0.0.1:4173/。
远程控制电脑可以帮助查看项目，但不能作为手机本机部署成功的证据。
如果你没有手机终端权限，就指导我在 Termux 操作，每轮最多给 3–5 条命令，
等我返回结果再继续；不要声称你已经执行了命令。

训练硬约束：讲解必须完整翻译题干，并按原顺序逐项解释所有选项，
每项包含核心义、本题语境义、完整中文翻译及选择或排除证据。
答对也不能省略错误项；SE 必须解释两个完成句为何等价。缺少原文则指出缺失，不能猜译。
没有真实作答或计时证据，不得记成完成、掌握或模考成绩。
先完成权限核验，再给本次唯一下一步。
```

## 提示词 2：首次在 Android 本机启动

```text
请带我在 Android 手机上本机运行 gre-data 学习平台。
仓库：https://github.com/zehouzhang0-lang/gre-data.git
请按 platform/mobile-prompts-20261006.md 和项目现有启动代码操作。

这次是本机部署：由手机 Termux 运行服务，手机 Chrome 打开本机端口。
先核实手机 Android 版本、CPU 架构、Termux 来源，以及是否已有项目副本。
优先使用 Termux 官方列出的 F-Droid 或 GitHub 安装来源；已有安装先检查，
不要要求卸载以免丢失文件。没有手机终端工具时，分批给命令，由我执行并返回结果。

部署步骤和约束：
1. 在 Termux 安装 Git、Node LTS、curl，并检查 node、npm、git 的实际版本。
   仓库要求 Node >=22；以 package.json 最新要求为准。每步失败先看错误再继续。
2. 在 Termux 私有主目录下选定项目目录，避免放在 /sdcard 或共享下载目录。
   目录不存在才 clone；已存在则先核对 git remote、分支和工作区状态。
   origin 必须为上述 HTTPS URL，不覆盖未知目录，也不把令牌写进 URL。
   仓库若需要认证，使用正常 Git 凭据/设备授权流程，秘密不进入聊天或仓库。
3. 拉取 main，使用本手机自己的 codex/android-study 分支；已有分支优先复用。
   配置正确 upstream 后再按仓库规则 pull --rebase --autostash。
   冲突保留现场并报告，禁止 reset --hard、强推或直接丢弃任一侧记录。
4. 完整读取 AGENTS.md、profile.md、scores.md、SCHEMA.md 和平台 README。
   在项目根目录依次运行 npm ci、npm run build、npm start。
   首次用前台 npm start 保留日志，保持 Termux 会话运行；不要假设退出终端后仍可用。
   当前启动器会复用已经响应的服务，代码更新时需先停止本项目旧服务再构建启动。
5. 新开 Termux 会话，检查 http://127.0.0.1:4173/api/state。
   确认返回的是本项目 JSON，读取实际词汇条数；不要只凭 HTTP 200 判断成功。
   再让我在同一手机 Chrome 打开 http://127.0.0.1:4173/。
6. 检查生词本来源目录、最近记录、资料库 PDF 和刷题题目能否显示。
   PDF 与题目索引必须来自手机副本的实际文件；首次索引可能需要等待。
   不用 Windows 路径，不把电脑上未同步的缓存当作手机已有文件。
   我实际完成并保存一题后，再验证刷新仍在；不要替我写虚假的测试作答。

兼容问题：仓库有 canvas、PDF、构建工具等原生依赖。只有安装或运行输出证明
原生 Termux 不兼容时，才给我 PRoot-Distro + Debian 的替代步骤。
先查看已安装 proot-distro 版本与 --help，再采用该版本支持的安装语法，
在 Debian 内重新确认 Node >=22。不要复制不匹配的 node_modules，
不要通过删除包锁文件、禁用校验或绕过沙箱掩盖错误。手机不需要 root。

平台 AI 单独检查 /api/ai/status：现有默认 gpt-5.6-terra、medium。
这与手机 ChatGPT 对话里选择的模型不是同一个设置；URL 参数不能证明模型切换。
新设备不会继承电脑的 Codex CLI 登录；Android 上 CLI 和运行环境是否兼容必须另验。
AI 不可用时保留基础背词和刷题功能，明确标记，不自动换付费 API 或升级 sol/astra。
如需我在 ChatGPT 手动请求讲解，也必须提供完整题干、全部选项及实际作答，不能编造。

验收要分别报告：手机环境、依赖安装、构建、接口、手机浏览器、实际保存恢复、
Git 同步、AI 可用性；没有证据的项目写“未验证”。
现在只给我第一组必要操作，等我反馈。
```

再 pull --rebase --autostash；出现冲突停止同步并报告。

## 提示词 5：手机打不开或 AI 不工作时排查

```text
我的 Android GRE 平台出现问题，请根据 gre-data 的
platform/mobile-prompts-20261006.md、platform/README.md 及实际日志排查。

先确认报错发生在哪层：ChatGPT 仓库连接、Termux Git/Node、依赖安装、构建、
Node 服务、Chrome、PDF/题目索引、Git 同步，还是可选 AI。
每轮只给最小的 3–5 条诊断操作，等待非敏感结果再决定下一步。

核对命令究竟在手机、远程电脑还是云端；不要混淆各自 localhost。
手机切后台后打不开时检查 Termux 服务是否还在，以及系统后台限制；
4173 被占用时先确认占用者，不能批量杀死所有 Node 进程。
不要把改成 0.0.0.0、关闭 Host/Origin 校验、公网隧道当成本机访问的必要步骤。
GitHub 读取成功不代表手机已拉取；Chrome 打开成功不代表进度已 push；
AI status 配置正确也不等于实际讲解已成功生成。
保留数据、包锁和原日志；需要任何破坏性动作时先解释具体影响，不直接重装或清空目录。

AI 失败时保留作答，维持 gpt-5.6-terra/medium 的成本偏好，不自动换付费 API。
讲解缺少完整题干翻译或任何选项的意思、翻译、取舍证据时，应判定不合格，
补齐并验证页面实际展示，不能只说已换模型或只检查后端字段。
最终给出已验证原因、已完成修复和未验证部分，不把猜测写成诊断结论。
```

## 安装者参考：已核对的本仓库事实

以下用于检查手机助手给出的步骤，不是已在手机执行的命令日志。

- `package.json` 当前要求 Node >=22；构建为 `npm run build`，前台服务为 `npm start`。Termux 提供 `nodejs-lts` 包，具体安装后的版本需在手机核对。[官方包定义](https://github.com/termux/termux-packages/blob/master/packages/nodejs-lts/build.sh)。
- 服务只监听 `127.0.0.1:4173`，并保留同源校验。手机本地部署可沿用这一设计；没有必要为此开放公网。
- 包锁包含 `@napi-rs/canvas` 的 Android ARM64 及 Linux ARM64 依赖。存在安装包不等于已经验证整个平台可运行；CPU 架构、Android 环境、字体/PDF 渲染和构建仍需实际检查。
- 可先在已有 Termux 内检查 `uname -m`、`node -v`、`npm -v`、`git --version`；尚未安装相关包时的候选命令为 `pkg update`，随后 `pkg install git nodejs-lts curl`。以实际输出决定下一步，不能跳过版本检查。
- 在已经正确克隆、认证且依赖安装成功的项目根目录，执行 `npm run build`，成功后执行 `npm start`。另开同手机终端运行 `curl -fsS http://127.0.0.1:4173/api/state`；此输出包含个人学习资料，只需反馈是否正常及必要字段。
- AI 默认值来自 `platform/server/ai-coach.mjs`；后台环境变量可能覆盖模型，因此验收读 `/api/ai/status`。本次没有在手机安装 CLI 或验证登录。
- 目前有 10 份受 Git 跟踪的教材 PDF；仍需检查手机 clone 是否完整。派生题目缓存位于 `.gre-platform/`，不随仓库同步；首次打开可能重新索引。
- Android 后台可能终止 Termux；初次使用保持会话运行，遇到中断再检查系统后台设置。断网时本机已有资料与基础功能的可用性须实测；Git 同步和新 AI 请求需要网络。当前项目没有承诺完整 PWA 离线模式。
- 页面摘词目前依赖右键；手机触控体验尚未真机验证。基础做题可用不能等同于每个交互都完成了手机适配。

正式验收应由用户在手机完成实际练习并核对保存结果。本次只交付提示词与核查依据，没有部署外部服务、购买服务或修改手机环境。
